Tipos, Tamanhos & Regras SQL
Regra 1
Chaves Primárias (PK)

Toda tabela deve ter uma coluna identificadora única (ex: id ou id_cliente) garantindo que nenhuma linha seja idêntica a outra.

Regra 2
Chaves Estrangeiras (FK)

Nos vínculos 1:N (Um para Muitos), a Chave Estrangeira sempre é posicionada na tabela dependente (lado N).

Regra 3
Relações N:N (Muitos para Muitos)

Nunca são implementadas diretamente: desmembram-se em uma tabela associativa intermediária com as PKs compostas.

2. O Dicionário de Dados: O Contrato Técnico

O Dicionário de Dados é o documento técnico de referência onde cada campo físico do banco tem seu tipo, restrições e finalidade minuciosamente definidos antes de rodar os scripts DDL.

Padrão de Nomenclatura Recomendado: Utilize sempre snake_case em letras minúsculas (ex: data_nascimento, preco_unitario, status_pagamento). Evite acentuação, espaços e caracteres especiais em nomes de tabelas ou colunas.

Exemplo de Especificação: Tabela clientes

Nome da Coluna Tipo de Dado Tamanho Obrigatório (NOT NULL) Chave (PK/FK) Descrição / Regra de Negócio
id INT UNSIGNED - SIM PK (Auto Increment) Identificador numérico exclusivo do cliente.
nome VARCHAR 120 SIM - Nome completo do titular da conta.
email VARCHAR 100 SIM UNIQUE E-mail de autenticação e comunicação.
cpf CHAR 11 SIM UNIQUE CPF gravado apenas com números (sem traços/pontos).
data_cadastro DATETIME - SIM - Data e hora exata do cadastro no sistema.

3. Guia de Escolha dos Tipos de Dados no MySQL

A escolha correta do tipo de dado economiza gigabytes em disco e memória RAM, além de acelerar as buscas do banco de dados:

Tipo SQL Quando Utilizar? Exemplo Prático
INT UNSIGNED Números inteiros positivos (IDs, quantidades, contadores). id INT UNSIGNED
VARCHAR(N) Textos de tamanho variável até N caracteres (nomes, endereços). cidade VARCHAR(80)
CHAR(N) Textos de tamanho fixo exato (sigla UF, CPF puro, CEP). estado CHAR(2)
DECIMAL(M, D) Valores monetários e números de precisão exata (nunca use FLOAT). preco DECIMAL(10,2)
DATE Datas simples sem informação de horário. data_nascimento DATE
DATETIME Data e hora completas para registros de transação e logs. data_pedido DATETIME
BOOLEAN / TINYINT(1) Estados binários de Verdadeiro (1) ou Falso (0). ativo BOOLEAN
