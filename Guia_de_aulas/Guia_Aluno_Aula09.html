A Regra de Ouro da Integridade: Nunca é possível declarar uma Chave Estrangeira se a Chave Primária correspondente não existir previamente na tabela pai!

2. Laboratório de Reconstrução Idempotente

SQL • Script Idempotente do Banco Retro-Vault MySQL 
SET NAMES utf8mb4;

DROP DATABASE IF EXISTS db_retro_games;
CREATE DATABASE db_retro_games 
  CHARACTER SET utf8mb4 
  COLLATE utf8mb4_unicode_ci;

USE db_retro_games;

CREATE TABLE desenvolvedoras (
    id_desenv INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL UNIQUE,
    nacionalidade VARCHAR(50) DEFAULT 'Desconhecida'
) ENGINE=InnoDB;

CREATE TABLE consoles (
    id_console INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    nome_console VARCHAR(50) NOT NULL
) ENGINE=InnoDB;

CREATE TABLE jogos (
    id_jogo INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    titulo VARCHAR(150) NOT NULL,
    ano_lanc YEAR NOT NULL,
    preco DECIMAL(10,2) NOT NULL,
    id_desenv INT UNSIGNED,
    id_console INT UNSIGNED,
    CONSTRAINT fk_desenv_jogo FOREIGN KEY (id_desenv) REFERENCES desenvolvedoras(id_desenv),
    CONSTRAINT fk_console_jogo FOREIGN KEY (id_console) REFERENCES consoles(id_console)
) ENGINE=InnoDB;

3. Provocações Pedagógicas e Análise de Falhas

Provocação 1 (Erro 1451): Ao executar DELETE FROM desenvolvedoras WHERE id_desenv = 1;, o MySQL recusa a operação com o Erro 1451. O banco impede a exclusão porque existem jogos que dependem do estúdio Nintendo.
SQL • Comportamento do AUTO_INCREMENT pós-DELETE MySQL 
-- 1. Excluir o jogo de ID 2 (Sonic)
DELETE FROM jogos WHERE id_jogo = 2;

-- 2. Inserir um novo jogo
INSERT INTO jogos (titulo, ano_lanc, preco, id_desenv, id_console, nota_metacritic) 
VALUES ('Chrono Trigger', 1995, 450.00, 1, 1, 9.8);

-- 3. O novo jogo receberá id_jogo = 4! A lacuna do ID 2 nunca é reaproveitada.
SELECT * FROM jogos;
