Visões Relacionais (Views), Consultas Aninhadas e Gestão de Dados

Guia prático e conceitual sobre a camada de abstração em bancos de dados relacionais e rotinas operacionais de exportação, importação e backup.

1. O Conceito Fundamental: O Que é uma View?

Nas aulas anteriores, você dominou a arte de unir tabelas com INNER JOIN, LEFT JOIN, filtros e agregações. No entanto, em sistemas reais, consultas complexas com 20 ou 30 linhas não devem ser reescritas por programadores ou analistas a cada novo relatório.

Definição Técnica: Uma View (Visão) é uma tabela virtual baseada no conjunto de resultados de uma consulta SQL pré-definida. Ela possui linhas e colunas exatamente como uma tabela real, mas não armazena dados físicos adicionais no disco. Ela armazena apenas a definição da consulta no catálogo do SGBD.
Característica Tabela Física View (Tabela Virtual)
Armazenamento em Disco Ocupa espaço físico com todos os dados gravados. Ocupa zero espaço de dados (grava só o comando SELECT).
Atualização dos Dados Armazena o estado no momento da gravação. Sempre dinâmica: reflete os dados mais atuais das tabelas originais.
Forma de Consulta SELECT * FROM clientes; SELECT * FROM vw_relatorio_clientes;
Finalidade Primária Persistir e garantir a integridade das entidades. Abstrair complexidade, filtrar segurança e simplificar o acesso.

Os 4 Pilares: Para Que Serve uma View no Mundo Real?

Pilar 1
Simplificação e Abstração

Evita que os desenvolvedores backend precisem escrever consultas gigantes com 4 JOINs para exibir dados simples no front-end. Toda a complexidade fica encapsulada.

Pilar 2
Segurança e Privacidade (LGPD)

Permite conceder acesso para equipes externas ou analistas de marketing sem expor colunas confidenciais (como senhas, CPFs, cartões ou salários).

Pilar 3
Desacoplamento e Estabilidade

Se os nomes de colunas ou a estrutura das tabelas físicas mudarem em uma refatoração, basta atualizar a View. Os sistemas que a consultam não quebram.

Pilar 4
Padronização de Regras de Negócio

Garante que todas as áreas utilizem exatamente a mesma fórmula para cálculos críticos (ex: quantidade * preco_unitario descontando devoluções).

2. Laboratório Prático: Criando Views na TechStore Brasil

Vamos criar três visões estratégicas no banco de dados loja_teste para atender a diferentes setores da empresa.

2.1 Caso 1: View Operacional de Faturamento (Suporte e Expedição)

Esta visão conecta as 4 tabelas da loja e entrega uma tabela pronta com o subtotal de cada item vendido.

SQL • Criação de View Operacional MySQL 
-- 1. Cria ou substitui a View no banco
CREATE OR REPLACE VIEW vw_faturamento_pedidos AS
SELECT 
    p.id AS pedido_id,
    p.data_pedido,
    p.status,
    c.nome AS cliente_nome,
    c.cidade,
    c.estado,
    pr.nome AS produto_nome,
    pr.categoria,
    ip.quantidade,
    ip.preco_unitario,
    (ip.quantidade * ip.preco_unitario) AS subtotal
FROM pedidos p
INNER JOIN clientes c ON p.cliente_id = c.id
INNER JOIN itens_pedido ip ON p.id = ip.pedido_id
INNER JOIN produtos pr ON ip.produto_id = pr.id;

-- 2. Veja como a consulta agora fica simples e limpa:
SELECT pedido_id, cliente_nome, produto_nome, subtotal 
FROM vw_faturamento_pedidos
WHERE status = 'Processando'
ORDER BY subtotal DESC;

2.2 Caso 2: View de Marketing Seguro (Conformidade com a LGPD)

O time de marketing precisa disparar campanhas por estado, mas não pode ter acesso a endereços completos ou dados sensíveis.

SQL • View Anonimizada para Marketing MySQL 
CREATE OR REPLACE VIEW vw_marketing_clientes_ativos AS
SELECT 
    c.id AS cliente_id,
    c.nome,
    c.email,
    c.cidade,
    c.estado
FROM clientes c
WHERE c.id IN (SELECT DISTINCT cliente_id FROM pedidos);

-- Consultando clientes de SP que já compraram:
SELECT nome, email, cidade 
FROM vw_marketing_clientes_ativos 
WHERE estado = 'SP';

2.3 Caso 3: View de Alerta de Ruptura de Estoque (Compras)

O setor de compras precisa de um monitor em tempo real para itens abaixo do limite mínimo de segurança (menos de 15 unidades).

SQL • View de Monitoramento de Estoque MySQL 
CREATE OR REPLACE VIEW vw_alerta_estoque_critico AS
SELECT 
    id AS produto_id,
    nome AS produto,
    categoria,
    preco,
    estoque,
    CASE 
        WHEN estoque <= 5 THEN 'URGÊNCIA CRÍTICA'
        WHEN estoque <= 15 THEN 'REPOSIÇÃO NECESSÁRIA'
        ELSE 'ESTÁVEL'
    END AS nivel_alerta
FROM produtos
WHERE estoque <= 15;

-- Consultando a lista de reposição prioritária:
SELECT * FROM vw_alerta_estoque_critico 
ORDER BY estoque ASC;

3. Gestão de Dados: Importação, Exportação e Backup (Indicador 7)

Um bom profissional de banco de dados precisa garantir a segurança e a portabilidade das informações. O Indicador 7 do Senac atesta a sua competência em exportar e restaurar dados conforme as regras do SGBD.

  1. Exportação Estrutural Completa (Backup / SQL Dump)
    Gera um arquivo .sql contendo tanto os comandos de criação das tabelas/views (DDL) quanto os comandos de inserção dos dados (DML).

    No phpMyAdmin: Selecione a base loja_teste ➔ Clique na aba Exportar ➔ Escolha o método Rápido (ou Personalizado para selecionar tabelas específicas) ➔ Formato SQL ➔ Clique em Exportar.

  2. Exportação para Planilhas e Relatórios (Formato CSV)
    Utilizado para compartilhar dados com setores não técnicos (contabilidade, gerência) que abrem arquivos no Excel ou Google Sheets.

    No phpMyAdmin: Selecione uma tabela ou execute uma consulta na View ➔ No rodapé dos resultados, clique em Exportar ➔ Escolha o formato CSV (ou CSV para MS Excel) ➔ Baixe o arquivo.

  3. Restauração e Importação de Base em Ambiente Novo
    Simula o procedimento de contingência quando um servidor falha ou quando precisamos criar um ambiente de homologação idêntico ao de produção.

    No phpMyAdmin: Crie um novo banco vazio chamado techstore_homologacao ➔ Selecione este novo banco ➔ Clique na aba Importar ➔ Escolha o arquivo .sql de backup que você gerou ➔ Clique em Executar.

Atenção com a Ordem de Restauração: Ao importar scripts SQL manuais com restrições de chave estrangeira (FOREIGN KEY), as tabelas pai (sem dependência) devem sempre ser criadas e populadas antes das tabelas filhas. O phpMyAdmin já trata isso automaticamente nos dumps gerados por ele.
