Escrita do Minimundo, Versionamento no GitHub e Homologação de Requisitos

Estruturação de documentação técnica em Markdown, auditoria cruzada por pares (Peer Review) via GitHub Issues e tratamento formal de lacunas de escopo.

1. Documentação Técnica Como Código

Na aula passada, vocês colheram as informações de negócio e elaboraram um rascunho. Hoje, daremos um padrão profissional à documentação, versionando o arquivo minimundo.md no GitHub e submetendo o projeto a uma auditoria técnica rigorosa.

O Que é Homologação? É o processo formal de validação onde garantimos que todos os requisitos foram expressos sem ambiguidades, que não existem "buracos" de processo e que tanto os desenvolvedores quanto os clientes estão 100% alinhados sobre o que será construído.

2. Roteiro Prático de Execução em Bancada

  1. Refinamento e Formatação em Markdown
    Abra o rascunho do Minimundo da sua dupla. Verifique se os atores, ações e regras estão claros e sem jargões técnicos. Formate os títulos usando cabeçalhos #, listas com * e negrito com **texto**.
  2. Criação do Repositório e Push no GitHub
    Crie o repositório no GitHub para o projeto da dupla e suba o arquivo minimundo.md na raiz:
    Terminal • Comandos Git Bash / PowerShell 
    git init
git add minimundo.md
git commit -m "docs: adiciona especificacao inicial do minimundo"
git branch -M main
git remote add origin https://github.com/usuario/projeto-uc3.git
git push -u origin main
  3. Auditoria Cruzada (Peer Review)
    Acesse o repositório da dupla parceira sorteada pelo professor. Leia o minimundo.md procurando furos na lógica de negócio (ex: "O que acontece se o cliente devolver o carro com o tanque vazio? O sistema registra taxas extras?"). Abra no mínimo duas Issues detalhadas no repositório deles.
  4. Tratamento de Gaps e Fechamento de Issues
    Sua dupla receberá issues no seu próprio repositório. Para cada issue:
    • Se a regra entra: Atualize o minimundo.md localmente e faça commit com mensagem de fechamento (ex: git commit -m "ajusta politica de seguro. fecha #1").
    • Se a regra NÃO entra: Responda na Issue justificando educadamente que a funcionalidade está fora do escopo desta versão e encerre a issue.

3. Guia de Sobrevivência (Git, Markdown e Homologação)

Conceito Significado na Prática Exemplo
Markdown (.md) Formato de texto leve com tags de marcação interpretadas nativamente pelo GitHub. # Título, **Negrito**
GitHub Issues Canal integrado ao repositório para registrar tarefas, dúvidas de escopo, gaps e bugs. Issue #1: "Como registrar cancelamentos?"
Peer Review Revisão técnica entre pares onde colegas auditam o projeto para garantir qualidade antes da codificação. Auditoria cruzada entre as duplas.
Gap de Requisito Cenário do mundo real omitido ou esquecido na redação inicial da especificação. Não prever forma de pagamento parcelado.
Homologação Validação final e aceite do escopo com 100% das issues auditadas e resolvidas. Documento pronto para o DER/MER.
