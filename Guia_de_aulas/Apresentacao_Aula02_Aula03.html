💬 O Desafio da Tradução

O Dilema do Analista

"Fui contratado para modelar o banco de dados de uma Pet Shop. Por onde eu começo?"

Lembre-se sempre de uma premissa vital:

  • O banco de dados serve para solucionar um problema real e gerar valor ao negócio.
  • Mas o cliente final não fala SQL!
  • Ele desconhece conceitos de "Chaves Primárias", "Tabelas", "Campos" ou "Cardinalidade".
  • Nossa missão é aprender a escutar e mapear o negócio usando a linguagem dele.
🌍 Definição

O que é o "Minimundo"?

O Minimundo (ou Escopo do Sistema) é a descrição textual detalhada de uma parcela específica do mundo real que será informatizada.

  • O Recorte da Realidade: O mundo dos negócios é infinitamente complexo. O Minimundo serve para estabelecer limites bem delineados.
  • Fronteiras Claras: Ele descreve exatamente o que o sistema de banco de dados irá guardar e organizar, bem como o que ficará de fora do desenvolvimento.
🏆 Essencial

A Regra de Ouro do Minimundo

🚫 O que NÃO Fazer?

É expressamente proibido o uso de termos e jargões computacionais no corpo do documento:

  • "Tabelas de Clientes"
  • "Campo chave primária"
  • "Atributo estrangeiro"
  • "Relacionamento N para N"

👍 Como Deve Ser?

Deve ser elaborado em linguagem de negócios natural e acessível para qualquer pessoa leiga:

  • "Registrar dados dos Clientes"
  • "Código identificador de produto"
  • "Um cliente pode comprar vários produtos em uma venda"

O cliente de negócios deve ler o texto e assinar em baixo dizendo:
"Sim! É exatamente isso que a minha empresa faz e precisa!"

Exemplo Real

Reserva de Equipamentos

minimundo_reserva.txt UTF-8 
"Os professores da universidade precisam de um sistema para reservar equipamentos tecnológicos (como datashow e caixas de som) para suas aulas. 

O sistema precisa registrar os professores (através de CPF, nome completo e titulação acadêmica). 

As reservas são formalizadas com as secretárias do setor (que possuem CPF, nome e turno de trabalho). A reserva deve conter a data do evento, a hora de início da aula, a sala de aula e a lista de equipamentos solicitados. 

Todo equipamento é identificado por um número de tombamento patrimonial único, além de sua respectiva marca e tipo de aparelho..."

💡 Perceba: Não há menção a "tabelas" ou "chaves", mas a estrutura dos dados futuros já está transparente.

Exemplo Real

Acervo da Livraria Universitária

minimundo_livraria.txt UTF-8 
"A livraria universitária precisa organizar seu acervo bibliográfico e gerenciar seus empréstimos ativos. 

Precisamos armazenar de forma organizada os dados dos livros, que possuem um título, autor principal, ano de publicação e quantidade total de páginas. 

Os livros são emprestados ou vendidos diretamente para os alunos, que devem apresentar seu número de matrícula único e estar com a situação regular na biblioteca para realizar transações. 

Cada empréstimo deve registrar a data exata de retirada, a data prevista para a devolução, o aluno responsável e a obra correspondente que foi levada."
💡 Metodologia

Como Extrair Essas Informações?

Use este roteiro de perguntas para desvendar as necessidades do cliente:

1. Contextualização

Qual o problema central que a empresa quer resolver no dia a dia?

2. Atores & Elementos

Quem interage e quais objetos fazem o negócio funcionar?

3. Atributos

Quais características de cada item/pessoa precisamos salvar?

4. Filtro de Relevância

Quais dados NÃO importam para o sistema? (evite ruídos)

5. Regras de Negócio

Como estes elementos interagem e quais são as obrigatoriedades?

6. Limites (Escopo)

Quais as restrições? Ex: "Um aluno pode levar até 3 livros?"

🎯 Objetivos de Hoje

Ciclo de Qualidade de Requisitos

Nesta segunda etapa de modelagem, as duplas vão:

  • Estruturar em Markdown: Transcrever e organizar o Minimundo coletado em um arquivo formatado minimundo.md.
  • Controlar Versões com Git: Compartilhar, commitar e versionar os requisitos em um repositório GitHub.
  • Auditar Requisitos Alheios: Atuar como equipe de qualidade analisando e abrindo Issues nos projetos parceiros.
  • Homologar o Escopo: Sanar lacunas de lógica mapeadas, preparando o documento como "contrato" de modelagem.
⚠️ Prevenção de Erros

A Importância da Validação

"Furos de lógica na modelagem inicial geram retrabalho gigante no final do projeto."

Muitas vezes o cliente assume regras implícitas ou esquece de detalhes. Precisamos testar os limites do Minimundo com perguntas do tipo:

🔄 Ciclo de Vida

"O que ocorre se o cliente cancelar este pedido?"

🔒 Unicidade

"Podemos ter mais de um veículo com a mesma placa?"

💥 Exceções

"Como registramos multas ou avarias na devolução?"

🐙 Git & GitHub

Controle de versões e ramificações. Compartilhamento do arquivo fonte da especificação entre a dupla de analistas.

🚩 GitHub Issues

Centralizador profissional de debates e apontamentos. Usado para documentar bugs e furos identificados nos requisitos.

Issue #4: "Falta regra..."
🕵️ Dinâmica Colaborativa

Auditoria Cruzada (Peer Review)

Sua equipe de desenvolvimento atuará hoje como o time de QA (Garantia de Qualidade):

  1. Acesse o Repositório: Entre no GitHub correspondente à dupla que você foi encarregado de auditar.
  2. Analise o minimundo.md: Leia atentamente e procure por contradições lógicas, ambiguidade ou regras não explicadas.
  3. Abra GitHub Issues: Registre profissionalmente pelo menos 2 Issues detalhando estas vulnerabilidades identificadas.
  4. Auditoria Docente: O professor também auditará os arquivos de requisitos, abrindo Issues técnicas críticas!
🔧 Resolução de Problemas

Como Resolver as Issues Recebidas?

Ao receber apontamentos em seu repositório, você tem dois caminhos profissionais:

🟢 Opção A: Dentro do Escopo

Se o apontamento faz todo sentido e é essencial para o funcionamento do negócio:

  1. Ajustem o texto do minimundo.md no Git.
  2. Façam o commit citando o número da Issue no comentário:
git commit -m "Ajusta cancelamento. fecha #2"

💡 Isso atualizará o arquivo e encerrará a Issue no GitHub de forma automatizada!

🟣 Opção B: Fora do Escopo

Se o apontamento for muito complexo ou desnecessário para esta fase do projeto:

  1. Responda à Issue aberta no GitHub justificando sua decisão de forma profissional.
  2. Explique que a funcionalidade foi classificada como fora do escopo inicial da V1.0.
  3. Feche a Issue manualmente justificando a recusa.
🏁 O Contrato Final

Minimundo Homologado!

No término desta sessão de trabalho, sua dupla deve atingir os seguintes entregáveis:

  • O arquivo minimundo.md estruturado, completo e refinado na raiz do repositório remoto.
  • Todas as GitHub Issues (abertas pelos colegas e pelo docente) respondidas e encerradas de forma limpa.

📌 Este documento validado e assinado é o contrato do projeto. Ele será o guia exclusivo que usaremos na próxima aula para traçar o Diagrama Entidade-Relacionamento (DER).

Resumo da Dinâmica de Desenvolvimento

Conceito / Ação Significado / Efeito Prático O que evitar no documento?
Minimundo Descrição em linguagem natural e fluida do escopo do projeto. Evitar termos técnicos de banco de dados (tabela, chaves).
Markdown Estilo e marcação leve para documentar requisitos de forma legível. Evitar textos corridos sem títulos ou listas organizadas.
GitHub Issues Auditores registram furos e pontos cegos na especificação da equipe parceira. Evitar linguajar informal ou comentários não técnicos/críticas destrutivas.
Homologação Acordo final sobre o escopo que impede retrabalho durante a modelagem física. Evitar iniciar códigos ou modelagem DER sem fechar o Minimundo.
